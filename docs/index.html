Taste Skill：面向编程代理的企业级网站设计技能

Taste Skill 是一个面向 Claude Code、Codex 等编程代理的 Agent Skill，目标不是拼装通用落地页，而是按照 figma.com、x.ai 这类专业公司官网的标准，从业务简报出发完成页面分类、设计系统分配、真实素材装配、动效编排与真实浏览器验收。仓库主文档称当前版本为 2.5.1，核心可安装技能名为 design-taste-frontend，并提供安装命令、按业务类型路由的构建流程、检查器和完成门禁。它的价值在于把网页审美要求转化为可执行的脚本、模板和验收规则。

为什么热门

  • 项目关注度极高：用户提供的元数据显示约 11.98 万星标和 8030 个派生仓库，说明其在 AI 生成前端页面方向有广泛影响。
  • 切中 AI 建站同质化痛点：项目明确反对“通用落地页”，强调统一设计系统、真实产品界面、真实照片、品牌图标和克制的动效。
  • 提供完整质量闭环：不只是提示词，还包含配色与字体分配、版式分配、素材脚本、浏览器一致性检查、性能检查和完成门禁。
  • 按业务类型严格路由：软件、技术硬件和游戏页面才使用着色器与滚动场景，咖啡馆、酒店、商店和工作室等保持照片与排版主导，减少特效滥用。
  • 安装与运行门槛较低：文档称仅需 Node 22+ 和 Chrome/Edge/Chromium，不安装额外依赖、不需要 API 密钥，并提供 Claude Code、Codex 和克隆安装方式。
  • 维护活跃且反馈具体：变更日志记录了 2.5.1 的大量修复、社区贡献、门禁和移动端检查改进，显示项目仍在快速迭代。

核心能力

  • 业务分类与页面规划：构建前先把客户业务归入 software、gaming、tech、product、service 或 place，并按屏幕逐段规划页面。
  • 设计令牌与版式分配：通过 start.mjs 分配适合行业的配色和 Google Fonts 组合，通过 layout/deal.mjs 分配十一种经过测试的首屏版式。
  • 统一页面系统：以 starter.html、system.css 和 layout.css 约束桌面端一屏一节、左右内容边缘对齐、固定导航和单屏收尾页脚。
  • 真实素材装配：为软件和技术页面提供产品 UI 片段、组件和节点连线图；为地点、商店、酒店等页面提供策展照片、字体和平面色块；并解析真实品牌与界面图标。
  • 受控动效与 3D 效果：所有页面都有首屏入场和一至两个重点时刻；着色器、滚动场景和程序化 3D 仅用于软件、技术硬件和游戏页面，并受四个 WebGL 上下文上限及静态降级约束。
  • 文案质量控制：提供事实表、声音卡、读者问题驱动的页面结构，以及约 30 毫秒级文案检查器，用于识别模型腔、套话、虚构统计和重复修辞。
  • 真实浏览器检查：consistency.mjs、layout/check.mjs、perf.mjs 和 shoot.mjs 在无头 Chrome 中通过 HTTP 渲染页面，检查多断点下的空视觉、着色器失败、对比度、列错位、节高漂移、占位文案、虚构地址、慢网图片缺口、移动端碰撞和点击目标尺寸。
  • 完成门禁：gate.mjs 汇总检查器、版式检查和静态检查结果，输出 PASS、FAIL、OPEN、SETUP、ERROR 或 OFF，并将部分警告升级为失败；最多三轮，可有限豁免误报。
  • 多技术栈适配：空目录生成静态页面；已有 React、Vue、Svelte、Astro 或 Tailwind 项目按原技术栈构建；Next.js 简报按静态导出处理并在构建产物上检查。

输入与输出

输入

  • 自然语言业务简报，包括公司类型、目标客户、页面目标、内容事实和希望呈现的品牌气质。
  • 页面类型或行业线索，用于归入 software、gaming、tech、product、service、place，并可指定 cafe、yoga studio、developer tool 等行业。
  • 现有项目源码或页面 URL；空目录则生成静态页面，已有 React、Vue、Svelte、Astro、Tailwind 或 Next.js 项目则按原栈处理。
  • 客户提供的品牌资产、产品截图或照片；没有照片时使用技能内置的带授权资料照片，并明确标注为临时占位。
  • 运行环境：Node 22+、已安装 Chrome、Edge 或 Chromium；ffmpeg 可选；下载额外照片、字体或图标时需要网络访问。

输出

  • 一个按统一设计系统构建的公司网站页面，包含首屏、正文段落、导航和收尾页脚，可输出为静态页面或集成到现有前端项目。
  • 可直接使用的设计令牌与 head 资源，包括配色、Google Fonts 链接、:root 变量和首屏版式。
  • 本地化的品牌图标、产品 UI 片段、图表、照片和动效资源，以及照片来源的统一页脚署名。
  • 按业务类型生成的文案与经文案检查器识别的风险清单，包括模型腔、套话、虚构统计和重复修辞。
  • 真实浏览器检查报告、性能数据、整页与分段截图，以及按断点列出的 PASS、WARN、FAIL 结果。
  • 完成门禁状态：GATE: PASS、FAIL、OPEN、SETUP、ERROR 或 OFF，并附带豁免记录和未解决失败项。
  • 在已有项目中完成页面集成，或在 Next.js 简报中生成可检查的静态导出产物。

两个使用场景

场景一

一家初创软件公司需要快速做出接近 figma.com 或 x.ai 质感的官网，但团队没有专职视觉设计师，也没有现成的产品截图。产品经理把业务简报交给编程代理，代理加载 Taste Skill 后将业务识别为 software，分配配色、字体和首屏版式，使用内置产品 UI 片段与图表搭建功能卡片，加入少量着色器和首屏入场动效，再运行真实浏览器检查与完成门禁。这样解决的是通用落地页缺少品牌感、产品能力只能靠抽象插画表达、上线前多断点版式失真的问题。

场景二

一家本地咖啡馆或建筑工作室要改版现有网站，但没有专业摄影和设计系统。代理先审计现有页面，再把业务识别为 place，选择照片和排版主导的首屏与章节，使用带授权的资料照片作为临时占位并在页脚统一署名，全程不启用 WebGL，随后检查移动端文字碰撞、点击目标、表单标签和文案腔调。这样解决的是模板站视觉廉价、图片版权和来源不清、手机端内容重叠以及表单不可用的问题。

具体运作流程

  1. 1

    触发：用户要求构建或改版公司网站，编程代理加载 Taste Skill，并先读取项目简报、现有项目结构或待审计页面。

  2. 2

    分类与规划：代理把业务归入六类之一，规划首屏和每个正文段落到具体屏幕，并确定行业、页面类型和是否需要照片、产品界面或效果。

  3. 3

    读取资源并分配设计系统：代理把 assets/ 复制到项目，从 assets/starter.html 起步，运行 scripts/start.mjs deal --page <kind>，按需加 --trade，得到配色、字体链接、:root 令牌和首屏版式。

  4. 4

    搭建页面骨架：基于 starter.html、system.css 和 layout.css 落实固定导航、一屏一节、左右边缘对齐、首屏入场和单屏 footer.closing，并按分配到的版式填入内容。

  5. 5

    装配素材与文案：软件和技术页面从 assets/ui/、assets/components/ 和 assets/diagrams/ 取真实产品界面与图表，运行 scripts/icons.mjs 解析品牌图标；地点、商店和产品页面运行 scripts/photos.mjs 分配照片并生成页脚署名，同时按 copy-voice、copy-registers 等参考组织文案，并用 copy-lint.mjs 检查。

  6. 6

    编排动效与效果：通过 scripts/moments.mjs 为所有页面分配重点时刻，通过 scripts/effects.mjs 和 assets/scenes/ 仅在允许的业务类型中加入着色器或滚动场景，并保留手机、减少动效和无脚本降级。

  7. 7

    浏览器验证：运行 scripts/consistency.mjs、assets/layout/check.mjs、scripts/perf.mjs 和 scripts/shoot.mjs，在 1440、1024、820、768、390 以及门禁要求的 320 宽度下渲染页面，得到逐规则 PASS、WARN、FAIL、性能数据、整页和分段截图。

  8. 8

    完成门禁与交付：运行 scripts/gate.mjs index.html，汇总检查器、版式检查和文案检查，处理不超过五个有理由的豁免；若存在可修复 FAIL 则回到页面修复，最多三轮，最终以 GATE: PASS 或最后一轮 GATE: OPEN 结束，并交付页面、截图、检查报告和素材署名。

  • 本次分析只基于 README.md、CHANGELOG.md 和 examples/v2/CREDITS.md，未提供脚本源码、模板源码和测试数据；关于检查器覆盖范围、门禁行为和实际构建质量的描述属于文档声明，无法独立验证（推断）。
  • 星标总数 119849、派生仓库总数 8030 来自用户提供的项目元数据，README 中未展示这些数字；7 日新增星标和派生数据仍在积累，无法判断短期增长趋势。
  • “达到 figma.com 和 x.ai 水平”属于项目自我定位和营销表述，页面审美与专业度仍取决于简报质量、代理执行和人工复核，不能视为客观保证（推断）。
  • README 说明该仓库主要承载 design-taste-frontend 一个技能，其他旧技能已迁移到独立仓库；因此不应把迁移项目的全部能力都算作本仓库当前内置能力。
  • 照片来自 Wikimedia Commons、Unsplash 等开放档案，授权因图片而异；使用者必须遵守 examples/v2/CREDITS.md 和各来源的许可要求，临时资料照片也不能冒充客户自有场景、员工或产品。
  • 运行依赖 Node 22+ 和 Chrome/Edge/Chromium，额外照片、字体和图标下载需要网络；ffmpeg 仅可选，未安装时 WebP 输出和手机裁切等能力可能受限。
  • 门禁允许对误报进行有限豁免，且最多三轮；这意味着检查通过不等于绝对没有视觉或可访问性问题，仍可能存在被豁免的失败项或检查未覆盖的情况。
  • 着色器和滚动场景只面向软件、技术硬件和游戏页面，地点、商店、酒店和服务类页面被有意限制为照片与排版主导；如果需求要求所有页面都使用 WebGL，会与该设计约束冲突。
